## Story boundary

Everything runs in story state: no agent work, installs, schedules, permissions, settings persistence, notification delivery, or account pairing. Evidence panels are labeled preview evidence. CI runs, TODO excerpts, and conversation history are illustrative fixtures; `d4ef105bc` is an actual repository commit. The Slack example is an illustrative connection, not a claim about current catalog availability.

The build-your-own variant starts from **Hooks**, found in the current BB Community catalog (`https://github.com/MacHatter1/bb-plugin-hooks.git`, catalog range `^0.4.0`). Its webhook and credential support make it the closest starting point for the example. The accepted story starts a thread building the user's own plugin; it does not install or modify Hooks. This is a catalog-based template choice, not a source security audit.

The phone QR encodes the shared **Phone landing** story, which contains the same Release summary question. It opens that exact prototype after the owner's BB Connect sign-in. App deep links, account pairing, and cross-device persistence belong to a product implementation.

Attention uses the existing `AppToastContent` presentation and thread attention glyph. It previews notification content within the app frame; it does not emit an operating-system notification. The open action reveals the waiting thread.

Accepted and installing stories hold their named state for review. In the interactive flow, installing advances to done, and the notifications confirmation disappears after three seconds. Reading stops after 30 seconds without results and leaves the composer usable. A denied notification hint stays absent when returning from Settings. The Suggestions switch and dismissal operate only within the story.

## Components and provenance

The frame directly imports `SidebarProvider`, `Sidebar`, `SidebarInset`, `SidebarMenuButton`, `AppPageHeader`, and `PageShell`. Messages, thread status glyphs, both composers, model controls, settings rows, switch, buttons, and responsive popovers are production components. Fixture sidebar items are composed from those primitives without loading a live account.

- **#5395:** no presentation code retained. The sidebar card is retired; the contextual notification moment informs the quiet Hint. Its eligibility/permission plumbing could inform later product work, but its card is not the starting surface for this design.
- **#4991:** retained `InlineConfirmation` and adapted the `SuggestionCard` typography, surface, and structure to separate the primary action, source chip, and dismiss button. Sound presentation starting point; removed the Tips feed, gallery, and feature catalog.
- **#4986:** no catalog-card code retained. It is sound for browsing a named catalog entry, but too much UI for a single outcome card; the proposed install uses Next step and inline status.
- Connect's QR rendering pattern is reduced to one QR image in `plugins/connect/guidance-qr.prototype.tsx`, using Connect's existing `qrcode` dependency.

Only story/prototype code, its Ladle style source, and a Ladle adapter export for the existing thread status glyph are changed. There is no product wiring or PR. Shipping requires brsbl's sign-off.
