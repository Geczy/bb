## Primary CLI provenance and path reasoning

On 2026-10-13 the official npm latest package was `@anthropic-ai/claude-code@2.1.296`. Its published optional platform packages were downloaded without installation or execution. Both archive SHA-512 digests were checked against registry integrity. Exact package URLs, integrity and extracted executable SHA-256 values are in [provenance.json](provenance.json). Registry metadata, tarballs and extracted binaries are alongside this handoff. No source repository commit is published (`gitHead` absent); the immutable versioned archives are the primary source.

- Linux source: `@anthropic-ai/claude-code-linux-x64@2.1.296`.
- macOS source: `@anthropic-ai/claude-code-darwin-arm64@2.1.296`.
- The published native binaries contain bundled JavaScript. Read-only extraction of relevant snippets is in [verified-path-rules.txt](verified-path-rules.txt), [linux-source-excerpts.txt](linux-source-excerpts.txt) and [darwin-source-excerpts.txt](darwin-source-excerpts.txt). These are source inspection, not a macOS runtime verification.
- CLI config directory: `(process.env.CLAUDE_CONFIG_DIR ?? join(homedir(), '.claude')).normalize('NFC')`. No trimming, tilde expansion, absolute resolution, dot-segment resolution or realpath before hashing. The filesystem's normal path semantics still apply when joining filenames.
- With no storage override, for a truthy explicit config dir, the production OAuth Keychain service is `Claude Code-credentials-` plus the first **eight lowercase hexadecimal SHA-256 characters of the NFC config-dir string**. Explicitly choosing the default directory still uses a suffix. Absent/empty values use the unsuffixed service.
- Credential storage: when `CLAUDE_SECURESTORAGE_CONFIG_DIR` is defined, nonempty selects its NFC string; empty selects NFC `join(homedir(), ".claude")`. If unset, storage uses the NFC config dir. Credentials file: `<effective storage dir>/.credentials.json`. A defined empty storage override uses the unsuffixed Keychain service even with custom settings; a nonempty override hashes its NFC string with the same eight-character rule, before path joining. Missing custom stores never borrow defaults.
- Account metadata: the CLI prefers `<NFC config dir>/.config.json` when it exists, otherwise `join(process.env.CLAUDE_CONFIG_DIR || homedir(), '.claude.json')`. The latter uses the original environment string, not the NFC string. The repair honors the custom legacy path; the absent-profile default account path remains BB's existing `~/.claude.json`.
- BB's public plugin-discovery resolver in `packages/plugin-sdk/src/vendor-plugin-roots.ts` trims and expands paths relative to home. That shipped public contract is deliberately untouched; reusing it would hash the wrong service for CLI profiles. Selection belongs privately to the existing `provider-maintenance.ts` owner shared by health and usage/account reads.
- `buildSessionOptions` forwards the environment unchanged except for context configuration. Provider maintenance reads the bridge process environment. This repair concerns the host's `CLAUDE_CONFIG_DIR` settings profile and the vendor's `CLAUDE_SECURESTORAGE_CONFIG_DIR` credential-storage precedence. Per-thread env overrides, API-key auth, custom OAuth endpoints, and credential-manager policy remain outside this repair. Relative paths remain relative to the executing process; no new host/thread cwd contract is introduced.
- [Official settings docs](https://code.claude.com/docs/en/settings) confirm that `CLAUDE_CONFIG_DIR` relocates user settings/history/plugins and describe the account/config file. Exact hash and precedence facts above come from the published packages, not inference from the docs.
